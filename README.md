# Core Rental — Your Bali Office, Delivered.

Rent fully-equipped office setups — desks, chairs, monitors, plants, coffee
machines and tropical extras — to digital nomads and startups in Bali,
**month-to-month**. Design your dream workspace on a visual canvas, then rent it.

> **Demo** — this is a frontend MVP with no payment and no backend. The Rent
> flow ends in a demo confirmation. Product decisions are recorded in
> `specs/DECISION_RECORD.md`.

## Live

▶ **https://core-workspace-rental.vercel.app** — open the demo and try it.

## How to use

- **Design** — in the Builder, pick a chair and desk, then add monitors, lamps
  and plants to your workspace (tabs filter the catalog; use the × on any
  placed item to remove it).
- **Browse** — the Store lists rentable products by category (Chairs, Desks,
  Accessories).
- **Review** — the Summary shows your line items + monthly total; add a
  delivery location.
- **Rent** — hit _Rent This Setup_ and type the demo phrase `this is a demo`
  to confirm. The order is then cleared and a confirmation is shown.

## Architecture

Feature-based vertical slices over shared layers:

- **`src/features/{home,builder,store,summary}`** — one feature per product
  surface (marketing, workspace designer, catalog, checkout), with barrel
  exports and colocated tests.
- **`src/shared/{data,domain,state,hooks,ui,types,config,observability}`** —
  the unified catalog + API hook, pure business rules (caps, exclusivity,
  validation), the cart reducer + localStorage persistence, reusable UI, and
  the PII-free structured logger.

**Data flow:** the committed `products.json` (generated by
`scripts/generate-catalog.ts`) is served by `/api/products` → fetched with
TanStack Query → filtered by the feature views → cart state lives in a
validated reducer persisted to `localStorage` → rendered by the shared UI.

See `specs/tech-architecture/tech-stack.md` for the full structure and
`specs/adr/` for the architectural decisions.

## Testing

- **Vitest** unit/integration, colocated beside source — with an 80% branch
  coverage gate on `shared/domain` (pure business logic).
- **Playwright** E2E in `e2e/` running against the production build — positive
  flows plus the negative flows N1–N11 (empty cart, 404, caps, removal,
  exclusivity, partner exclusion, image fallback, API failure, security
  headers, corrupt storage, delivery validation).
- E2E expectations import `products.json` with spec-local arithmetic — they
  never import app pricing logic (a pricing bug must fail the test, not echo
  itself).

## Deploy

**Vercel zero-config** — push to `main` and Vercel builds + deploys
automatically (detects Next.js; no `vercel.json` needed, no `vercel` package).
The live build is at the URL in the **Live** section above.

Local preview of a production build:

```bash
pnpm build && pnpm start   # then open http://localhost:3000
```

Optional CLI previews: `vercel dev` / `pnpm dlx vercel deploy --preview`
(dev-time tooling only — never a runtime dependency).

**CI:** GitHub Actions (`lint → typecheck → unit → coverage → build → e2e →
belt-and-braces`) runs on every push/PR and gates merges. Security headers
(CSP etc.) are served by `next.config.ts` on every route — asserted by E2E N9.

## AI Workspace Designer (dev)

The builder's **Design with AI** panel turns a natural-language request
("fancy gaming workspace, max Rp 30 juta") into a validated builder design.
It is **env-gated**: the route returns `503 ai_disabled` until a provider is
configured, so the deployed demo is unaffected until you choose to enable it.

- **Local dev (free, offline):** run LM Studio on `localhost:1234/v1` with a
  tool-calling model (default `gpt-oss-20b`; `devstral-small-2-2512` also
  works), then copy `.env.example` → `.env.local`:
  ```bash
  AI_BASE_URL=http://localhost:1234/v1
  AI_MODEL=gpt-oss-20b
  ```
- **Production (OpenAI):** set `OPENAI_API_KEY` + `AI_MODEL` in the Vercel
  project env vars. Costs real money per request — guarded by a best-effort
  in-memory rate limit (~10 req / 10 min / IP) and output caps.
- **Design contract:** the AI discovers products via tools (never the prompt),
  and the route re-validates every SKU + the monthly total server-side — a
  hallucinated or over-budget design can never be applied. The user's prompt
  text is never logged or tracked (PII-safe). See `specs/adr/0007-ai-design-route.md`.
