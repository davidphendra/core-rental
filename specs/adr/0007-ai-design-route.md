# ADR 0007 — AI workspace design route

- **Status:** Accepted (e10 session rulings 1–8)
- **Context:** Users wanted to describe a workspace in natural language ("fancy gaming workspace, max Rp 30 juta") and have the app populate the builder. The demo has no auth and one public, read-only API route. Options considered: client-side LLM calls (deployed site cannot reach a laptop-hosted LM Studio — rejected), OpenAI-only (rejected for dev cost), and a provider-switchable server route (accepted). A second question was how the LLM learns the catalog: inlined prompt context vs tool-based discovery — tools won (hallucination-free SKUs by construction).
- **Decision:** A single `POST /api/ai-design` route using the Vercel AI SDK (`ai@7`), provider-switchable via env: `AI_BASE_URL` set → LM Studio / any OpenAI-compatible endpoint (`createOpenAI({ baseURL })`, officially supported pattern per ai-sdk.dev); else OpenAI API (`OPENAI_API_KEY`). The model discovers products by calling tools (`searchCatalog`, `getSetupTotal`, `finalizeDesign`) — the catalog is never in the prompt. **Validation trust boundary: only catalog-validated designs may touch builder state** — the route re-validates every SKU (existence, slot/cap match), recomputes totals from real prices, and re-verifies a server-extracted budget (`extractBudgetIdr`), retrying once before refusing honestly. Demo-lite guardrails (env gate 503, in-memory rate limit 429, output caps) bound cost on the public endpoint. Observability emits facts only (`ai.request`/`ai.design_applied`) — the user's prompt text is never logged or tracked (PII-safe by construction, consistent with ADR 0006).
- **Consequences:** The route cannot return a hallucinated or invalid design; a hostile prompt can at worst produce a rejected design or a refusal (S1/S4/S7 of `specs/security/epics/e10/THREAT_MODEL.md`). The OpenAI key stays server-side (S3). Rate limiting is per-instance — documented limitation for a demo (S2). AI is dev-only until a key is configured in the deployment env (env gate). Tool-calling requires a tool-capable model (LM Studio models verified: gpt-oss-20b default, devstral-small-2-2512 alternative). Non-streaming v1; streaming and multi-turn chat are deferred (out of scope).
